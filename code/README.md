# Simulation code for the IISE 2027 paper

Companion code for **"Risk-Aware and Cost-Effective Validation of Manufacturing Knowledge Across Changing Production Systems"** (IISE Annual Conference 2027 submission).

## What is here

| File | Purpose |
|---|---|
| `des_simulation.py` | SimPy 5-station serial-flow line (textbook layout inspired by Kempf 1994 MiniFab). Used to generate physical ground truth for two of the knowledge items; parameters live in `paper/tables-sources.md`. |
| `bayesian_trust.py` | Bipartite trust network: factor-level latent Z_f with Pr(Z_f = 1) = 1 - delta_f, item-level V_k via noisy-OR, evidence updates via Bayes + mean-field factor credit assignment. |
| `decision_agent.py` | The proposed agent. Decision risk = min(use, discard, escalate) per item. R(a) = expected drop in total risk via one-step posterior-predictive imputation. Myopic argmax over R(a) / cost. |
| `baselines.py` | B1 full revalidation, B3 no evidence sharing (ablation), B4 random, B5 max-uncertainty + cheap activity. |
| `run_experiments.py` | Runs Scenario S1 (equipment upgrade) over 50 instances x 10 replications x 5 policies = 2500 runs. |
| `analyze_results.py` | Aggregates `results/raw_results.csv` into `results/results_table.csv`, `results/results_table.md`, and `results/figure_cost_vs_incorrect_reuse.png`. |
| `requirements.txt` | Pip install list. |

## How to run

```
pip install -r requirements.txt
python run_experiments.py      # ~5 minutes on a modern laptop
python analyze_results.py      # produces the paper's Table 3 and Figure 2
```

Results land in `code/results/`.

## Ground-truth independence from the method's graph (reviewer concern M6)

The simulator's ground truth is generated by an ORACLE knowledge graph (`build_oracle_graph` in `run_experiments.py`), not by the method's own graph G. The oracle keeps 70% of the method's edges (with jittered weights), drops 30%, and adds two hidden factors the method cannot see. Ground truth for each item V_k^true is sampled from a noisy-OR over the oracle's edges. This means the method operates under a graph that is correct in broad strokes but wrong in detail, which is the realistic setting and a fair handicap.

## Model equations (reviewer concerns M2, M3, M4, M5)

### Factor prior (M2, M3)

    Pr(Z_f = 1) = 1 - delta_f

    Pr(V_k = 1 | Z) = prod over f: (k, f) in E of (1 - w_kf * (1 - Z_f))

### Evidence likelihoods (M5)

| Activity a | Pr(e = pass | V_k = 1) | Pr(e = pass | V_k = 0) | Coverage per call |
|---|---|---|---|
| Trial run | 0.95 | 0.10 | 1 item |
| Shadow mode | 0.85 | 0.20 | all pending items (fixes m3) |
| Formula-based re-derivation | fuses directly on factors with sigma = 0.20 (not conditionally independent) | | 1 item |
| Expert judgment | 0.75 | 0.25 | up to 3 items per call (fixes M5 consistency with Sec. 3) |

Formula re-derivation uses a noisy observation of the factor-level estimate because it depends on the same factors as the item, and therefore is NOT conditionally independent of V_k given V_k alone. We fuse at the factor level with Gaussian-conjugate weight 1 / sigma^2 (`BipartiteTrustNet.update_from_formula`).

### Posterior update (M2)

For activities with conditionally independent evidence:

    p_k_post = L(e | V = 1) * p_k_prior / ( L(e | V = 1) * p_k_prior + L(e | V = 0) * (1 - p_k_prior) )

Then credit is assigned back to each dependent factor in proportion to its current contribution to the item's doubt (edge weight x (1 - pz)), see `update_from_item_evidence` in `bayesian_trust.py`.

### Decision rule (M4)

Per-item decision risk under current trust p_k:

    r(k) = min( (1 - p_k) * c_WU,  p_k * c_WD,  c_E )

with c_WU = 100 CU (wrong use), c_WD = 25 CU (wrong discard), c_E = 15 CU (escalate).

Total risk R_tot = sum over pending k of r(k). Agent chooses:

    a* = argmax over a of  ( R_tot(before) - E[R_tot(after a)] )  /  c_a

The argmax is over four activity types and their eligible item sets. The policy is myopic (one-step); multiple activities per day are allowed while the remaining day hours (24 h) and remaining budget both permit.

## Reproducibility

All randomness runs through `numpy.random.default_rng` seeded from the master seed `SEED = 20261119` in `run_experiments.py` plus per-instance and per-rep offsets. Rerunning `python run_experiments.py` produces an identical `raw_results.csv`.
